# AGENTS.md

For anyone, person or AI agent, who picks up this repository. The user-facing description is in README.md; designs
and their technical reasons are in [docs/design.md](docs/design.md). 1ms.dog's operating notes (accounts, who
maintains what, the shared server) are in its private repository, 1ms-shell.

## What this is

**httpslatency**: real HTTPS latency from the machine it runs on to the services 1ms.dog (github.com/yt1988/1ms.dog)
tests, with the page's verdict, in a terminal. One Go binary, no dependencies beyond `golang.org/x/sys`, 10 languages,
a menu when run without options, a result link like the page's, and self-update from GitHub releases.

| File | What it does |
| --- | --- |
| `main.go` | options, the run, output choice; `baseline` and `status` subcommands are dispatched first |
| `measure.go` | the measurement: per service one uncounted request opens DNS, TCP, TLS; then timed requests on that connection |
| `list.go`, `services.json` | the service list: fetched from `https://1ms.dog/services.json` on every run, this copy built in as a fallback |
| `verdict.go`, `output.go` | the page's judgement and the terminal / Markdown / JSON output |
| `texts.go`, `webtexts.go`, `plural.go`, `i18n.go` | words: the tool's own (`texts.go`), the page's (`webtexts.go`, generated), plural forms |
| `origin.go` | where it runs from (1ms.dog's `/_ms/me`, Cloudflare as fallback); Taiwan's fixed name |
| `share.go` | the result link, shortened with 1ms.dog's shortener |
| `update.go`, `reexec_*.go` | update check and self-update (checksums verified) |
| `baseline.go` | `httpslatency baseline --out DIR`: what 1ms.dog's Tokyo server runs hourly (below) |
| `compare.go` | `--compare` and `httpslatency status`: read the Tokyo baseline from `https://1ms.dog/baseline.json` |
| `deploy/baseline/` | the server's systemd service and timer, and its README (the pattern for scheduled jobs) |
| `install.sh`, `install.ps1` | installers, also served by 1ms.dog at `/i` and `/i.ps1` |

Rules the code keeps:

- Nothing is uploaded: only the requests to the services, the list and location from 1ms.dog, the shortener when a
  link is printed, and the update check. `--offline` turns all of 1ms.dog off. The usage text and READMEs say so;
  change them with the behavior.
- The result link never carries an address.
- Every key of `texts.go` is in every language (the test checks); words the page also shows come from the page
  (`webtexts.go`, generated by the site's `scripts/cli-texts.mjs`; don't edit by hand).
- Output fits 80 columns in the long languages (German, Russian): check them when changing a line.

## Build and test

Needs Go (the version in `go.mod`).

```bash
go vet ./... && go test ./...
go build -o httpslatency .
./httpslatency -c ai -n 3          # a short run
./httpslatency --compare -c dev    # with the Tokyo baseline beside each service
./httpslatency status -c ai
```

`HTTPSLATENCY_NO_UPDATE=1` skips the update check; `HTTPSLATENCY_BASELINE_URL` points `--compare` and `status` at a
local `summary.json`. GitHub Actions: `ci.yml` checks formatting (`gofmt`), vet, tests, a build and a short real run on every push; `services.yml` copies 1ms.dog's service
list into `services.json` daily.

When the page's words change (grades, groups, regions, uses, the verdict), regenerate in a checkout of the site:
`node scripts/cli-texts.mjs ../https-latency-test-cli/webtexts.go`.

## Release

Push a tag `vX.Y.Z`. `release.yml` builds 12 platforms
(`-ldflags "-X main.version=X.Y.Z"`), writes `checksums.txt`, attests the builds and publishes the release with the
installers. 1ms.dog's `/v` and `/dl/<tag>/<file>` mirror it within minutes. Check: `curl https://1ms.dog/v`, download
one binary from `/dl/vX.Y.Z/`, compare its checksum, run `--version`.

## Running the baseline on your own server

`httpslatency baseline --out DIR` measures every service once and writes static JSON for a status page or for
`--compare`. Run it on a schedule from a Linux server. It needs outbound HTTPS only: no inbound port, no secrets.

1. Build on any machine: `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w -X main.version=<v>" -o httpslatency .`
   (`GOARCH=arm64` for an ARM server).
2. On the server: a system user for it (`<app-user>`), a root-owned folder for the binary (`/opt/<app>/`) and a
   results folder it owns (`/srv/<app>/`).
3. Upload the binary; when replacing it, upload to `httpslatency.new` and `mv` it over, so a run never starts on half
   a file.
4. Install the service and timer from `deploy/baseline/` (they carry 1ms.dog's user and paths: change `User`,
   `Group`, `ExecStart` and `ReadWritePaths` to yours; the timer runs on the hour). `systemctl daemon-reload`, start
   the service once, then `systemctl enable --now` the timer.
5. Publish the results folder read-only over HTTPS with CORS from any web server, and point the site's `BASELINE`
   (`src/worker.js` in the 1ms.dog repository) and this tool's `baselineURL` (`compare.go`) at your copy.
6. Verify: the service's `Result` is `success`; the folder has `latest.json`, `summary.json` and `days/<today>.json`;
   the published `summary.json` answers with CORS.

A run takes about 12 s and 10 MB, about 0.8 MB of traffic. The unit allows writing only to the results folder, keeps
no capabilities and sends nothing but errors to the journal. The day files are the only state: `summary.json` is
rebuilt from them on every run. File formats and retention: `deploy/baseline/README.md`.
